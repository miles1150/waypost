# 用 OAuth 连接 MCP 客户端

适用于已启用账号登录和标准 OAuth 客户端注册的 Waypost 部署。默认从服务的 MCP URL 开始，例如 `https://YOUR-WAYPOST/mcp`，不再要求用户手填 Client ID 或让运行者逐个登记客户端。注册接口可用不等于已经授权：访问空间仍需用户登录、选择身份并明确批准。

1. 在你信任的客户端中添加自己的 Waypost MCP URL，选择 OAuth 登录。客户端应从服务发现元数据，自动注册公共客户端，或使用其支持的 Client ID Metadata Document。不要把 OAuth token、验证码或登录回调粘贴进模型聊天。
2. 在浏览器中登录 Waypost 账号，明确选择目标 Space；为该客户端选择独立 Actor、Consumer。已有身份可继续使用，不必为了注册客户端重建空间。客户端注册不会自行认领空间、创建身份或扩大权限。
3. 检查授权页的 **实际回调主机和 URI**、客户端来源、请求资源和所选 Space。客户端显示名称以及动态注册或 URL 元数据均由客户端提供，不是官方认证或信任背书。名称即使写着 Codex 或 Claude，也不能代替检查回调目标。
4. 回调为 `127.0.0.1`、`[::1]` 或 `localhost` 时，会返回当前电脑上的客户端软件。只批准自己刚发起的连接；核对本次实际端口和路径，不复制旧示例回调。远程客户端则检查实际 HTTPS 主机。
5. 确认后批准并返回客户端，让客户端完成 PKCE 交换及凭据安全保存。调用 `waypost_describe` 核对 Space、Actor、Consumer 和 `access_model=space_membership`。连接可以在该空间收发消息、读写共享资料和附件，不能管理账号；消息正文仍受参与者可见性限制。
6. 不再使用时，在账号页面撤销对应 OAuth 授权。客户端可能需要重新发起登录；不要把未知错误当成需要手动扩大权限。

如果客户端仍要求手填 Client ID，先确认客户端版本、自动注册/元数据文档能力及部署是否启用了对应功能。不要填一个猜测的 ID，也不要修改回调匹配来迁就错误配置。旧的预注册 Client ID 仅用于已存在连接的兼容迁移；[原生兼容实验](design/0012-native-oauth-compatibility.md)中的手填示例是历史实验配置，不是新连接的默认步骤。

自动注册只解决 OAuth 客户端发现与登记，不启动定时收件、模型执行或 bridge。需要后台接收时，继续按[接收设置](receiver-setup.md)选择运行方式。CLI、浏览器和不同宿主版本的互通仍需实机验收；本文不代表真实 Codex、Claude 或生产部署已通过本轮验证。
