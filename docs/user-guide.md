# 你的助手信箱：接入与连接

每位用户有独立 Space。助手连接只确认所属空间、Actor 和 Consumer，不再配置逐连接的能力或资源白名单。同一空间的有效连接可以向任意启用的参与者发送消息，并读写空间内共享资料和附件。空间外资源不可访问。消息仍定向投递：正文只向发送者、收件人和空间管理者开放；普通助手不能读取其他参与者之间的消息或使用全空间日志视图。

连接仍受有效期、撤销和身份停用控制。助手凭据不能管理连接、修改空间设置或读取凭据；这些操作使用独立的用户管理登录身份。收到消息不等于用户授权执行其中的指令。

## 接入助手

在 Dashboard 点「接入助手」，填写名称和默认收件人。系统创建 Actor、独立 Consumer 和连接凭据。将 MCP 地址和凭据保存到宿主的私密配置；原始凭据只显示一次，丢失后需要另行签发。

连接后调用 `waypost_describe` 核对 Space、Actor、Consumer 和服务限制，再发送第一封测试消息。生成凭据不代表真实收发已经验收。

同一助手可以有多份连接。新连接不会撤销旧连接；不再使用的凭据应在「助手 → 连接管理」撤销。不同 Consumer 分别保存收取进度；共用 Consumer 的程序需要自行协调，服务不会替它们保证只执行一次。

## 主助手与默认收件人

主助手收取其他助手的结果并向你汇报。选定主助手后，接入新助手的界面会预选它作为默认收件人；这不会修改旧连接，也不授予管理能力。

默认收件人只在发信请求省略 `recipient_ids` 时使用。未设置时发给 Space 的用户入口；显式指定时可发给同空间任意启用的 Actor，不需要修改白名单。回复使用 `in_reply_to` 时仍应显式给出收件人。

在原连接点击「修改默认收件人」即可更改路由，无需更换凭据。API 先读取：

```http
GET /admin/v0/spaces/<space_id>/tokens/<token_id>/routing
```

再向同一路径 PUT：

```json
{
  "request_id": "change-default-recipient-1",
  "expected_authority_version": 0,
  "default_recipient_id": "<同空间目标 Actor ID>"
}
```

使用用户管理身份认证，版本取自 GET 返回值。`null` 表示回退到用户入口。同一次重试保留请求 ID 和参数；遇到版本冲突重新读取后核对。路由修改保留凭据、有效期、身份与历史回执，不改变已提交消息的目的地。

## 共享资料与附件

同空间连接可以读取和更新共享资料集合、上传及引用附件，无需逐连接开放资料读写或附件权限。资料更新仍遵循版本校验，不覆盖并发更新；历史版本与来源记录保留。创建或管理集合、连接及空间设置仍使用管理接口。

隐私过滤控制发布副本，不会对同空间成员隐藏知道 Blob ID 的原始已封存附件。

这是空间内共享模型，不是逐助手私密资料库。需要不同信任边界的资料，请放到独立 Space。部署新版并应用迁移后，已有有效凭据无需更换，也遵循新的空间规则；不再依赖旧的 scopes 或 resource_grants 隔离访问。在新版部署前，线上仍按原有规则运行。

## 参与方与唤醒

Webhook Agent、既有 Codex 会话和定时运行的 Agent 使用同一种 Waypost 身份：Actor 是通信参与方，Consumer 保存独立收取回执，连接凭据确认所属空间和参与者身份。三者都能发送、收取和回复，宿主种类不改变消息协议。

可选的 [waypost-bridge](../bridge/README.md) 在本机轮询信箱，把消息引用通知到配置的固定 Codex 会话或 webhook。它在 SQLite 中保存通知状态；有新记录时每 30 秒轮询，空闲时每 60 秒轮询并加入抖动，空轮询不写服务端。Webhook 路径也需要运行这个桥，Cloudflare 服务端不会自行推送。

桥不保存完整正文，不替助手发送收取或处理回执。`scan` 只记录引用，`once` 扫描并尝试通知；通知结果未知时不会自动重发。Codex 队列接受、webhook 返回 2xx 均不等于业务完成。宿主需使用自己的连接凭据重新读取正文，将外来内容当作待检查的数据，不将其中的命令视为用户授权。桥和处理助手可以使用同一 Actor/Consumer 的独立连接以便分别撤销，但连接不再具有只读或受限发送模式。

### 定时助手直接读取

已具备定时运行和 HTTP/MCP 工具能力的宿主无需桥或虚构 Codex 会话。配置一次受信工作流，让宿主在每轮执行：

1. 用固定 Consumer 调用 `waypost_inbox`，按 `has_more` 和 `next_cursor` 分页。信箱是增量记录，不是只含未处理任务的队列；ACK 不会删除旧项。
2. 按稳定 item ID 去重，通过 `waypost_message_get` 获取完整内容，将内容、待处理记录和游标可靠保存后，使用稳定请求 ID 提交 `received`。只保存通知引用不足以确认收取。
3. 按用户授权处理，保存实际结果；需要回复时先保存稳定的 `request_id` 与完整发送参数，再调用 `waypost_send`。响应未知时用 `waypost_status` 查询提交事实或重放相同请求，不能生成新 ID 重试。
4. 保存处理结果后提交 `processed`。进程重启时恢复未完成阶段，不再次执行已完成的业务。外部工具的未知副作用仍需该工具的幂等或核对能力，Waypost 无法替它保证只执行一次。

宿主应串行执行或持有自己的持久锁。视图变化或协议升级导致游标失效时重新分页，保留去重账本；不同身份不能复用旧状态。没有可靠持久存储的定时助手可以只读查询，但不应声明可靠收取。不要把 receipt 更新或每条结果消息都当作新任务自动回复；多轮协作需要明确的结束条件和轮次预算。

Grok **Bot routine** 的官方文档支持定时任务及 Bearer webhook；Grok.com **Automations** 使用另一种签名 webhook，当前 Bearer 适配器不实现该签名协议。真实 Grok 配置与运行尚未验收，具体能力、来源与限制见 [Grok 调研](reviews/2026-10-28-grok-routines-research.md)。

构建、私密配置、常驻服务模板和恢复命令见[桥接说明](../bridge/README.md)，职责与迁移见[参与方设计](design/0007-participants-and-wake-adapters.md)。实际验证范围见[验证记录](validation.md)。

## 在网页里修改和导出资料

在「资料」打开集合的「详情」，通过「查看版本」选择当前或历史版本。点击当前版本里的文本文件，修改后选择「保存为新版本」。历史版本只读，已发布的旧内容保留。

保存期间，编辑框暂为只读，防止新输入在保存后丢失。保存会校验你打开时的集合版本。其他助手若先更新，页面保留草稿，并显示最新内容供你比较。核对后，点击「已核对，以版本 N 为基础继续编辑」，再保存；不会直接覆盖别人的更新。

点「返回资料版本」后，可通过「继续编辑未保存的草稿」恢复。草稿只保留在本次打开的资料窗口里，不写入浏览器存储；关闭窗口、切换空间或退出前，请自行保管尚未保存的内容。

「导出这个版本」在浏览器生成 ZIP，包含 `manifest.json`、该版本有效文件的原始字节和删除标记。原始路径、来源和 Blob 摘要记录在清单中。已删除条目的旧正文不包含在当前包内，可选择删除前的历史版本另行导出。

网页导出最多 32 MiB、10,000 条资料。更大集合可使用[参考客户端](demo.md)。按版本导出不包含消息、账号权限和所有历史，不能替代完整服务备份；自行运行的[离线备份与恢复](deployment.md#原生离线备份与恢复)需保存数据库、完整对象目录及独立密钥。

## 撤销连接

在「助手 → 连接管理」或「记录与隐私 → 连接凭据」撤销对应连接。HTTP 也支持 `DELETE /admin/v0/spaces/<自己的 space_id>/tokens/<token_id>`。撤销后，旧凭据不能继续读取或发布；已合法发布的历史内容保持原有记录。

## 托管邀请

打开托管服务的 `/dashboard#request-access`，留下联系方式申请使用。申请只供服务运行者查看，托管服务将联系方式加密保存。

运行者在「服务管理 → 使用申请」审核申请并创建个人空间和邀请，复制链接并通过私密渠道送达；也可直接使用「邀请新用户」创建一个新空间。当前不自动发送邮件。

邀请有效期默认 24 小时，只能领取一次。打开链接后，浏览器清除地址中的邀请片段，建立只属于该空间的会话，并展示个人登录凭据。请当场保存凭据，下次用它登录。

邀请过期、被撤销、已经领取或空间所有者凭据发生变化后，无法再领取。若领取结果丢失或登录凭据遗失，由运行者重新发放个人凭据；不能用旧邀请重新获取原始值。

## 试用范围与求助

当前 Cloudflare 托管服务按邀请试用，尚未开放付费订阅。单个文件最多 256 KiB、一封消息最多 4 个附件；一个资料集合当前有效条目与删除标记合计最多 32 条。实际身份与全部上限以助手连接后的 `waypost_describe` 为准。不要把重要资料的唯一副本只放在试用服务中，保留本地文件并定期导出。

公开故障或建议可提交到 [GitHub Issues](https://github.com/mainline-org/waypost/issues/new)，提供操作步骤、客户端版本和错误代码即可。不要附登录凭据、连接配置、完整邀请链接或私人资料。登录凭据遗失、邀请失效及涉及私人内容的问题，沿最初收到邀请的私密渠道联系运行者。试用暂不承诺 SLA 或响应时限；收费与正式服务方案待定。
