# 你的助手信箱：接入与授权

使用我们提供的 Cloudflare 托管服务，先申请邀请，收到私密链接后领取自己的空间并保存登录凭据。自己运行时，用数据目录的登录凭据进入，在「服务管理 → 创建用户空间」准备自己的空间。运行服务的人负责准备空间和登录信息；自己运行时就是你。

每位用户使用独立的空间（协议中称 Space）。登录凭据用于管理自己的空间，助手使用另外签发的连接凭据。需要同时使用两个用户的资料时，分别接入两份授权连接；修改资源 ID 不会跨越空间边界。

## 默认连接能做什么

「接入助手」为助手创建身份、独立 Consumer 和仅含 `message.send` 的连接凭据。未选主助手时，默认向你发信；选定主助手后，可以把它设为新连接的默认收件人。首次接入不创建记忆集合，也不开放收信、附件或资料权限。MCP 的 `waypost_describe` 返回实际权限与上限，助手仍可查询自己发信的提交结果。

在宿主的私密 MCP 配置中保存连接后，请助手发送第一封信。Dashboard 的「信箱」只显示发给用户入口的消息；「记录与隐私 → 全部消息」保留当前空间内的所有交接。生成凭据只表示身份已创建，真实收到来信才能确认宿主完成连接。

旧版服务和已有连接可能有更多权限。升级界面不会自动缩小旧凭据；需要时在原连接上编辑权限；凭据遗失或泄露时才撤销并重新签发。

助手是否自动收信取决于宿主的调度。可以手动请助手检查 Waypost，也可以在具备调度能力的宿主中安排定时检查。

## 按需开放更多能力

在「助手 → 连接与权限」或「记录与隐私 → 连接」找到原连接，点击「编辑权限」。选择所需能力与资源范围，点击「审阅修改」，比较当前与保存后权限，再保存。原凭据、Actor、Consumer、到期时间和历史回执保持不变，无需重新配置 MCP。已撤销、已过期或身份已停用的连接不能通过编辑恢复。

收信需要 `message.read`，主动确认回执需要 `receipt.write`。上传附件或记忆文件需要 `blob.write`。使用资料版本时，按用途选择 `memory.read` 或 `memory.write`；需要一个自己的集合时，可勾选「为这个助手创建自己的资料集合」。

资料读写权限也覆盖该助手自己拥有的集合。其他助手的集合需要同时选择相应能力与具体集合授权。未选择额外收件人时，只能向用户入口发信；选择后，用户入口仍包含在这份界面签发的收件范围中。

若权限被其他页面同时修改，编辑器保留草稿并显示最新权限。核对后选择「保留草稿，基于此版本重新审阅」，再次比较并保存，避免覆盖其他修改。

新增读取权限包含获准范围内的历史记录。读取范围变化后，客户端遇到 `CURSOR_SCOPE_CHANGED` 应刷新 `waypost_describe`，重置扫描游标并按稳定 item ID 去重；原有回执不删除。仅修改发送或写入权限不会使新版游标失效；旧版游标仍可能要求重读。移除权限无法撤回已经收取的副本。

需要独立设备连接或更换凭据时，仍可签发新连接。新连接不会自动撤销旧连接；原始凭据只展示一次，关闭详情后即从页面移除。

这是现有 scope、资源授权与到期机制的界面。任务授权、人工批准和第三方秘密代理仍为后续设计。

## 主助手与接入助手

主助手是你主要对话的助手，负责收取其他助手的结果、整理进展并向你汇报。接入助手使用独立的连接交付结果。现在正在对话的助手也可以担任主助手；选择哪个产品，由你决定。

在「助手」页选择「选为主助手」，再编辑其原连接，明确开放收信、回执和发信能力。角色选择本身不扩大权限。之后接入 Today、Instinct 或 Grok Bot 时，默认收件人可选择主助手；这份连接仍只有发信能力。默认收件人由服务返回，发送方不必手填 Actor ID。这些名称都是使用示例，实际接入要求运行环境支持 HTTP MCP 或 HTTP API。

主助手检查自己的信箱，可靠保存后确认收取，再按实际处理阶段发送回执。它的执行与调度由运行环境负责。Dashboard 的「信箱」显示发给你的汇总报告；「记录与隐私 → 全部消息」保留助手之间的交接。

既有连接仍默认向用户入口发信。更换主助手不会改写旧连接；需要新的投递目标时，为原连接增加收件人授权，让助手明确指定该收件人；管理 API 也可同时修改默认收件人。同一请求重试时仍投递给首次保留的收件人，当前连接也必须具有该收件人的授权。

## 允许两个助手互相通信

先接入两个助手，在发信助手原连接的「编辑权限」里增加收信助手为收件人。收信助手开放 `message.read` 与 `receipt.write`。双方重新查看 `waypost_describe` 后，即可发信、检查信箱，并在可靠保存或处理后确认回执。

使用管理 API 时，先读取完整当前授权：

```http
GET /admin/v0/spaces/<space_id>/tokens/<token_id>/permissions
Authorization: Bearer <用户登录凭据>
```

再向同一路径发送 `PUT`，提交完整期望授权，保留没有修改的 scope、资源范围和默认收件人：

```json
{
  "request_id":"edit-connection-2026-10",
  "expected_authority_version":0,
  "scopes":["message.send","message.read","receipt.write"],
  "resource_grants":{
    "recipient_ids":["<收信助手 actor_id>"],
    "memory_read_collection_ids":[],
    "memory_write_collection_ids":[],
    "blob_reference_ids":[]
  },
  "default_recipient_id":"<收信助手 actor_id>"
}
```

`expected_authority_version` 使用 GET 返回的当前值，不能固定填零。同一次重试使用相同请求 ID 和内容；版本冲突后重新读取、比较，再用新的请求 ID 提交。普通助手凭据不能修改自己的授权。

## 共享一个记忆集合

在读取助手原连接的「编辑权限」里开放 `memory.read`，勾选允许读取的资料集合。为其他助手开放写入时，使用 `memory.write` 和可写集合授权；来源助手仍保留所有权。通过上述 API 编辑时，对应字段为 `memory_read_collection_ids` 与 `memory_write_collection_ids`，必须同时保留其他现有授权。

## 本地通知桥

可选的 [waypost-bridge](../bridge/README.md) 在本机轮询信箱，把消息引用通知到配置的固定 Codex 会话。它在 SQLite 中保存通知状态；有新记录时每 30 秒轮询，空闲时每 60 秒轮询并加入抖动，空轮询不写服务端。

桥不保存完整正文，不替助手发送收取或处理回执。助手仍通过现有 HTTP/MCP 读取和处理；队列接受通知不代表任务完成，投递结果未知时不会自动重发。构建、私密配置、常驻服务模板和恢复命令见[桥接说明](../bridge/README.md)，职责与权限边界见[设计方案](design/0006-local-bridge-and-connection-permissions.md)。真实宿主与部署验收以[验证记录](validation.md)为准。

## 在网页里修改和导出资料

在「资料」打开集合的「详情」，通过「查看版本」选择当前或历史版本。点击当前版本里的文本文件，修改后选择「保存为新版本」。历史版本只读，已发布的旧内容保留。

保存期间，编辑框暂为只读，防止新输入在保存后丢失。保存会校验你打开时的集合版本。其他助手若先更新，页面保留草稿，并显示最新内容供你比较。核对后，点击「已核对，以版本 N 为基础继续编辑」，再保存；不会直接覆盖别人的更新。

点「返回资料版本」后，可通过「继续编辑未保存的草稿」恢复。草稿只保留在本次打开的资料窗口里，不写入浏览器存储；关闭窗口、切换空间或退出前，请自行保管尚未保存的内容。

「导出这个版本」在浏览器生成 ZIP，包含 `manifest.json`、该版本有效文件的原始字节和删除标记。原始路径、来源和 Blob 摘要记录在清单中。已删除条目的旧正文不包含在当前包内，可选择删除前的历史版本另行导出。

网页导出最多 32 MiB、10,000 条资料。更大集合可使用[参考客户端](demo.md)。按版本导出不包含消息、账号权限和所有历史，不能替代完整服务备份；自行运行的[离线备份与恢复](deployment.md#原生离线备份与恢复)需保存数据库、完整对象目录及独立密钥。

## 撤销连接

在「助手 → 连接与权限」或「记录与隐私 → 连接凭据」撤销对应连接。HTTP 也支持 `DELETE /admin/v0/spaces/<自己的 space_id>/tokens/<token_id>`。撤销后，旧凭据不能继续读取或发布；已合法发布的历史内容保持原有记录。

## 托管邀请

打开托管服务的 `/dashboard#request-access`，留下联系方式申请使用。申请只供服务运行者查看，托管服务将联系方式加密保存。

运行者在「服务管理 → 使用申请」审核申请并创建个人空间和邀请，复制链接并通过私密渠道送达；也可直接使用「邀请新用户」创建一个新空间。当前不自动发送邮件。

邀请有效期默认 24 小时，只能领取一次。打开链接后，浏览器清除地址中的邀请片段，建立只属于该空间的会话，并展示个人登录凭据。请当场保存凭据，下次用它登录。

邀请过期、被撤销、已经领取或空间所有者凭据发生变化后，无法再领取。若领取结果丢失或登录凭据遗失，由运行者重新发放个人凭据；不能用旧邀请重新获取原始值。

## 试用范围与求助

当前 Cloudflare 托管服务按邀请试用，尚未开放付费订阅。单个文件最多 256 KiB、一封消息最多 4 个附件；一个资料集合当前有效条目与删除标记合计最多 32 条。实际权限与全部上限以助手连接后的 `waypost_describe` 为准。不要把重要资料的唯一副本只放在试用服务中，保留本地文件并定期导出。

公开故障或建议可提交到 [GitHub Issues](https://github.com/mainline-org/waypost/issues/new)，提供操作步骤、客户端版本和错误代码即可。不要附登录凭据、连接配置、完整邀请链接或私人资料。登录凭据遗失、邀请失效及涉及私人内容的问题，沿最初收到邀请的私密渠道联系运行者。试用暂不承诺 SLA 或响应时限；收费与正式服务方案待定。
