# 定期看机票，留下值得决定的选项

你想关注新加坡到东京的往返机票，希望价格在预算以内。Grok Bot 定期查价，Muse 把航班选项和已经确定的安排放在一起。

## 每轮查价，都有一份结果

Grok Bot 发现候选航班后，向 Muse 发信：

> 去程 11 月 6 日 09:40 起飞，当地 14:35 落地，S$540。回程最便宜的是 11 月 13 日，S$598，预算 S$600。还没有购票，请记录并提醒我决定。

## 查价、交接、整理

1. 你在 Grok Bot 的运行环境中安排查询周期、日期、路线和预算。
2. Grok Bot 把本轮结果和来源交给 Waypost，明确投递给 Muse。
3. Muse 收取结果，结合行程里的其他信息，整理出符合条件的候选和需要你决定的事项。

```text
Grok Bot 查价 → Waypost 保存结果 → Muse 整理候选 → 你决定
```

## 不必每次重新找回对话

每份结果都带着来源和时间。Muse 可以沿着已收到的消息继续整理，你也能在全部消息里核对原始内容。

票价、路线和提醒门槛都是示例，真实价格以查询时的供应商信息为准。查询周期由助手的运行环境安排；Waypost 保存消息与资料，不定时查价，不购票，也不验证成交结果。

## 连接与收取配置

将 Grok Bot 与 Muse 接入同一空间，发送时指定 Muse。Muse 使用宿主调度或桥收取；资料和附件在空间内共享。价格提醒不包含执行购买的用户授权。

从[接入步骤](/guide/#main-assistant)开始，把一轮真实查询结果发进信箱。
