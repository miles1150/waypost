# 账号自主管理与运营者认证退役

本轮在代码分支实现，默认保持既有行为。不代表生产已禁用运营者、迁移空间、撤销或删除凭据。

## 产品边界

Google 账号是日常管理入口；不新增持久空间恢复密钥。用户接受 Google 账号丢失后没有独立的应用内恢复通道。不能据此引入邮件自动认领、数据库直接改归属或隐式恢复超级管理员。

旧空间迁移所需的认领和已有空间密钥机制暂时保留。保留兼容路径不等于要求每个空间建立恢复密钥；已有凭据是否撤销，应在实际迁移和验收后另行确认。禁用全局运营者也不会自动撤销已有 Space 级凭据。

## 默认兼容与显式禁用

计划配置：`WAYPOST_OPERATOR_MODE=enabled` 为默认；`disabled` 禁止全局运营者 bearer、登录和旧运营者会话，同时保留账号及普通 Agent 数据路径。禁用不等于封锁 `/admin/*`，账号 Dashboard 仍复用其中受限的读写入口。运营者模式与邀请模式是独立开关：`disabled` 不会自动关闭已有邀请兑换；面向账号入口的实际切换需同时设置 `WAYPOST_ONBOARDING_MODE=accounts`。已有空间密钥也不会随这两个开关自动撤销。

禁用时必须显式配置 OIDC、`WAYPOST_CSRF_SECRET` 和 `WAYPOST_CURSOR_SECRET`。两份签名秘密仅由服务端使用，不是用户登录或空间恢复凭据。它们须独立于运营者认证秘密，不能使用模板值。缺失必需配置时拒绝启动，不能自动生成一个新的管理员。

启用模式保留旧签名派生兼容；先配置独立签名密钥，再切换运营者模式。首次切换签名材料会影响已有 CSRF 表单或游标，应重新加载登录页面，并按客户端既有恢复流程重扫；已配置独立游标签名的服务可以保留该值，避免无谓游标变化。之后轮换运营者密钥不应影响使用独立密钥的 CSRF 与游标。

## 账号管理范围

账号只能管理当前选中且归属自己的 Space。新的管理操作使用独立账号 API，不向旧管理路由整体开放权限。管理写入需要同源、CSRF、近期有效会话，并在事务提交时复核账号状态、会话、选中空间和归属。

- 查询及撤销既有普通连接；不重新展示原始凭据。设备配对连接使用已有设备管理；正常 OAuth 连接通过授权族管理，缺失映射的孤立 OAuth token 仍可撤销。
- 查询及撤销 OAuth 授权族，撤销覆盖已有 access token；刷新和撤销竞争不能恢复授权。
- 管理空间内 Actor/Consumer 的停用及主助手选择。主助手是 `primary_actor_id` 设置，不是替换空间默认所有者 Actor/Consumer；保护默认所有者及当前主助手，避免误停后无法正常使用。
- 新设备继续使用已有配对协议获得凭据；不再增加一套可重复取回秘密的旧式签发协议。

禁用模式下 `/ready` 允许已认证且选中自有空间的账号或空间级所有者执行只读就绪检查，仅返回状态、schema 与环境；不恢复全局管理能力。

账号管理不授予全局空间枚举、他人空间访问、生产维护、加密密钥管理或运营者凭据重设能力。

## 迁移与上线顺序

1. 保持生产当前模式。确认目标 Google 账号与旧空间，完成经批准的既有运营者登录、空间管理凭据建立和认领；本分支不代替这个授权步骤。
2. 用该账号验证历史消息、附件、资料、设备配对、旧连接撤销、OAuth 撤销及主助手管理；只使用可回收的测试连接验证撤销，不误撤正在工作的 Mac/Grok 连接。
3. 私下配置独立签名秘密，验证页面、游标和桥；这属于生产配置操作，当前未执行。
4. 单独确认禁用目标后设置运营者模式；完整切到新版本并处理旧版本在途请求，不能把实例内开关宣称为跨版本即时撤权。验证旧运营者 bearer、旧会话和新登录均失败，账号与 Agent 正常；保留数据与加密密钥。
5. 是否删除旧运营者 secret、撤销迁移用空间密钥或删除兼容代码，分别根据实际依赖和授权处理。不要把开关切换等同于永久删除代码或数据。

不要求新增独立恢复密钥。出现 Google 故障时，不能自动重新启用运营者；只有获授权的部署管理员可以进行后续维护。Cloudflare 基础设施管理权限与 Waypost 应用运营者权限是不同边界。

## 验证计划与限制

隔离测试覆盖无运营者秘密启动、配置缺失拒绝、旧 bearer/会话拒绝、独立签名连续性、账号跨空间拒绝、会话过期或解绑与管理提交竞争、连接/授权族重复撤销、OAuth 刷新竞争、主助手并发更新及旧设备数据路径。实际 Workerd 使用合成身份和本地 D1/R2；真实 Google、已有 Mac/Grok 和生产模式切换必须独立验收。

本轮不操作生产权限。失去唯一 Google 身份而没有其他获授权管理路径时，无法保证应用内自行恢复；这是明确接受的产品取舍，不能写成已有恢复能力。

## 本轮本地验收

独立安全审查未发现剩余具体阻碍。隔离实际 Workerd 验证无管理员秘密的禁用启动、五类错误配置拒绝、保留旧秘密时全局 bearer/会话仍拒绝、账号及空间所有者就绪检查、旧 Agent 消息读写、账号管理范围、会话过期、空间切换、主助手 CAS 和旧迁移入口兼容。测试没有外发请求、没有生产操作，也没有签发新的恢复密钥。

数据库测试在初次认证返回后注入账号停用、解绑、清除选中空间、会话过期及近期认证失效，验证最终事务不撤销 token 或 OAuth family。主助手测试验证顺序执行的旧版本冲突和重放，不冒充同时请求竞争。UI 验证分页、绑定具体 Space 的操作及切换后旧控件失效。

完整 Rust 回归、26 项 Python、29 项 UI、native/Wasm strict Clippy、Worker 构建及文档检查为本轮验证范围。真实 Google、Mac/Grok、空间迁移和生产禁用尚未因这些测试完成。

## 账号进入 Dashboard

账号页只在当前会话已选中空间时提供 `/dashboard?auth=account` 入口。该模式的 JSON 与附件请求明确携带 `x-waypost-auth: account`，后端只验证账号会话；旧管理 Cookie 不能遮蔽账号身份，无效账号也不能回退为旧管理权限。该标记不授予权限，原有空间归属、CSRF 和最终写入授权检查继续生效。

登录会话之间不共享选中空间。未登录或未选空间时返回账号页处理，不要求输入空间密钥；成功认证后的数据加载错误保留错误提示，不能将服务错误伪装为密钥登录失败。真实 Google 浏览器验收仍需在本机执行，隔离测试不代替该验收。
