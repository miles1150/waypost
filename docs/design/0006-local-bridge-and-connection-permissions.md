# 本地通知桥与连接权限编辑

状态：已完成设计审查，进入实现与验收。本文规定目标行为，不表示已部署或已完成真实 Codex 验收。验收事实另记于验证记录。

## 问题与交付范围

现有助手连接只能创建或撤销。用户给同一个助手追加读取或资料权限时，需要重新配置凭据；这把授权调整与凭据更换绑定在一起。另一方面，Waypost 已能可靠保存消息，但不会自行通知用户本机的固定 Codex 会话。

本次增加原连接权限编辑和一个轻量本地通知桥。服务端仍负责消息、授权、共享资料与消费者回执；桥只负责发现新消息、可靠记录通知尝试、向固定会话投递。先支持个人约五台设备，不新增通用任务框架、本地 HTTP 服务或服务端调度器。

参考 Yobiru `906ef9698224` 的 `codex_bridge.py` 和 `codex_queue_client.py` 的未知投递处理。Yobiru 的 `tools/waypost_bridge.py` 是另一条双向文本转发路径；本次不移植 Friends、任务租约、Tailscale 接收端或该互通转发器。若复用或翻译上游代码，保留其 MIT 版权声明。

## 连接身份与可修改授权

保留现有 Actor、Consumer 和 token 模型。Actor 表示参与者，Consumer 保存独立收取进度，token 认证并关联授权。首期不增加独立 Connection 表。

提供两个管理操作：

| 操作 | 用途 |
| --- | --- |
| `GET /admin/v0/spaces/{space_id}/tokens/{token_id}/permissions` | 读取完整权限、资源范围、默认收件人及权限版本 |
| `PUT /admin/v0/spaces/{space_id}/tokens/{token_id}/permissions` | 带预期版本原子替换授权，记录审计 |

管理者从完整详情编辑，不能以只含 scopes 的旧列表记录作为完整授权提交。写入使用稳定请求 ID 与预期权限版本；重复请求可恢复，同 ID 不同内容冲突，过期版本要求刷新后重新比较。

成功更新保持 token 原值、Actor、Consumer、到期时间与历史回执不变，递增 token 的 `authority_version`。所有 grant 删除、插入、版本推进和审计必须在同一事务中由同一个获胜操作保护；CAS 失败的请求不能继续修改子表。拒绝已撤销、已过期、身份停用或跨空间的修改，不以权限编辑恢复凭据。

沿用现有空间所有者与管理员认证、CSRF 和 Origin 约束。普通助手凭据不能调用此接口，也不增加让助手自行扩大权限的 MCP 工具。

资源授权必须验证属于当前空间。空 `recipient_ids` 继续表示空间默认收件人，不能解释成无收件人。调整收件范围时，同时验证保留或指定的默认收件人仍在有效范围内。审计记录权限变化、时间和可识别的管理主体，不包含凭据原值或摘要。

## 读取视图与游标

新 `f3` 游标使用读取可见范围指纹，避免仅增加发送或写入权限就触发历史补读。指纹必须覆盖实际 feed 可见性依赖的读取 scopes、读取资料范围，并继续绑定 Space、Actor、Consumer、消费者视图版本和过滤器。权限提交的并发校验仍使用完整 `authority_version`，不能因读取指纹缩小而放松写入撤权保护。

保留旧 `f2` 游标验证路径，其完整授权指纹规则不变。旧游标在权限改变后可以返回 `CURSOR_SCOPE_CHANGED`；新页返回 `f3`。不能把旧指纹按新规则直接接受，否则可能沿用过期的读取边界。

读取范围改变时，客户端重置扫描游标并分页补读。新增读取权限默认包含该授权范围的历史记录，界面需说明这一点。去重按稳定服务来源、Space、Actor、Consumer 与 item ID 保存，不把权限指纹或游标版本放进通知去重键。只改变凭据、消费者或固定会话绑定时必须显式校验，不把旧队列静默改投。

## 一个本地进程，一个数据库

桥接使用独立 Rust crate，产物 `waypost-bridge`，与服务端在同一仓库维护。其 HTTP、SQLite 和进程依赖不进入 Cloudflare wasm 构建。

```text
Waypost HTTP 增量读取
        ↓
本地 SQLite：绑定、扫描游标、消息引用、通知证据
        ↓
官方 Codex CLI → 配置的固定会话
        ↓
助手通过既有 HTTP/MCP 读取正文并提交业务回执
```

消息引用和待通知记录与扫描位置一起提交，成功后才能推进本地扫描。桥不镜像正文、附件或记忆，不提供离线完整信箱。实际处理消息需要能够访问 Waypost。

桥只给消息生成通知，不把回执更新变成新的通知循环。通知包含本地受信配置和经过验证的消息标识，不直接拼接外部正文或标题。外部输入不能选择 CLI、命令参数、目标会话或宿主权限。

通知状态为 `pending → sending → accepted / unknown`。发送前先持久化 `sending`；进程崩溃后把未确认的 `sending` 视为 `unknown`。只有明确未开始投递的错误才可自动重试。超时、非零退出或不匹配的回执都不能证明未送达。未知状态只能依据固定会话中的有效通知证据或显式人工核对解决，不能因最近历史中没有找到标记就自动重发。

保存 queue ID、尝试次数、下次尝试时间和核对证据即可，不另建模型执行任务状态机。官方 queue 的接受回执只说明通知入队，不说明模型已开始或完成工作。

运行时持有单实例锁，SQLite、配置与凭据文件仅当前用户可访问。配置拒绝远程明文 HTTP（本机测试除外）、跨来源重定向和不明确的会话目标。401/403 暂停相关操作；恢复待投递记录时需检查当前读取授权，不能在撤权后继续投递旧引用。已被 Codex 接受的通知不能承诺撤回。

## 回执与 MCP 边界

桥只保存引用，因此不发送 `received` 或 `processed`。本地扫描位置只表示已经记录通知任务。助手可靠取得所需内容后才提交 `received`，记录本轮实际处理结果后才提交 `processed`；外部业务动作是否成功仍由真实工具回执证明。

复用 `waypost_describe`、`waypost_inbox`、`waypost_message_get`、`waypost_ack` 和 `waypost_status`。不增加普通助手的管理工具。权限更新后，下一次服务请求按新授权检查；客户端在权限错误或游标变化时刷新描述并恢复读取。MCP 宿主可能缓存工具说明，不能把工具列表当成当前授权依据。

## 五设备与 Cloudflare 免费额度

默认活跃时每 30 秒轮询，持续空闲后每 60 秒轮询，并加入少量随机抖动。有积压立即有界分页补收；网络错误、429、5xx 指数退避，遵守 `Retry-After`。每台设备只运行一个对应连接的桥，使用单实例锁防止重复轮询。

| 场景 | 五设备全天轮询请求 | 相对 Workers 每日 100,000 次免费额度 |
| --- | ---: | ---: |
| 每 30 秒 | 14,400 | 14.4% |
| 每 60 秒 | 7,200 | 7.2% |

这不包含消息处理、Dashboard、其他客户端或同账户其他 Worker。正常轮询发现延迟平均约 15 秒，空闲约 30 秒；错误退避时更长。

空轮询不发 ACK、不写 D1、不上传心跳、不每轮调用 describe。Codex 重试和通知账本保持本地。现有参考 Consumer 的空页 ACK 行为不能原样用于这个循环。

空收件请求仍有认证、增量读取和权限复核；D1 计扫描行而非返回条数。验收应检查无消息、有大量不可见记录、权限扩大补读三种场景的 D1 `rows_read`，以及 Worker CPU。尤其关注游标后有不可见记录时的重复扫描。先测量再考虑索引或扫描优化，不为五台设备先引入 WebSocket、Durable Objects 或服务器内部轮询。

官方限制依据：[Workers](https://developers.cloudflare.com/workers/platform/limits/)、[D1](https://developers.cloudflare.com/d1/platform/pricing/)、[R2](https://developers.cloudflare.com/r2/pricing/)。这些是设计预算，不是当前账户实际用量或已完成压测结论。

## 分发与运行

通过 GitHub Releases 分发按操作系统与架构区分的预编译压缩包和 SHA-256 校验文件。下载解压后即可运行，不要求用户安装 Rust、Python 或 Node。先支持前台与单次运行，提供 launchd/systemd 示例；不在安装时自动创建 Codex 会话、改变权限或登录账户。

更新替换二进制，私密配置和 SQLite 状态保留。数据库迁移需保持待投递及未知状态，不允许升级通过清空账本解决冲突。CI 分别验证 bridge 和服务端 native/wasm 构建。首期不做自动更新器，跨平台产物发布应明确各平台实际验证状态。

## 实施与验收顺序

1. 实现权限详情与原子更新、Dashboard 编辑、审计及 f3/f2 游标兼容。
2. 实现独立 bridge crate、稳定去重、Codex 投递与未知结果处理。
3. 完成 native、Dashboard、桥接故障测试和 Cloudflare wasm 构建；用真实 Worker runtime 检查 D1 批次语义。
4. 核对生产账户、Worker、D1/R2 绑定和旧版本，保存必要备份，再应用兼容迁移与发布。迁移与代码的回滚边界单独记录，不能把 Worker 回滚等同数据库回滚。
5. 从 cloud env 在隔离的合成测试空间验收同凭据增减权限、旧游标恢复、HTTP/MCP 互通及 bridge 的读取链路。测试凭据随后撤销，不触碰用户消息。
6. 对真实 Codex 官方 CLI 和明确的现有目标会话进行独立投递验收；模拟 CLI 测试不能冒充真实模型执行。没有可用宿主或会话时如实记录未验收部分。

最低故障矩阵包括：权限 CAS 竞争和响应丢失、撤销/过期/跨空间、保留未编辑 grant、仅发送权限变化、新读取权限历史补读、空轮询零写入、保存前后崩溃、queue 超时、错误回执、双进程、绑定替换，以及未知状态不会自动重发。

设计审查依据与处置见[评审记录](../reviews/2026-10-28-bridge-permissions-design.md)。
